## Status key

- **Supported:** current schema → projection → renderer can reproduce the approved job without material substitution.
- **Partial / lossy:** the content can be stored/rendered, but structure, hierarchy, interaction, data authority or responsive behaviour changes materially.
- **Unsupported:** no current body type and renderer can express the approved module.
- **Shell adaptation:** intentionally supplied by the production site rather than copied from the standalone preview.

Priority: **P0** blocks approval/fidelity; **P1** is required before publication but can follow the core set pieces; **P2** is production hardening/consistency.

## Recommended reusable schema contract

Do **not** implement a Portugal-only route first. The smallest faithful reusable vocabulary is:

1. **Presentation options on existing objects**
   - `insight.heroLayout`: `standard | splitSquare`.
   - `insightSection.presentation`: `standard | ruledRich`.
   - `insightSection.intro`: optional text and `headerLayout`: `stacked | split`.
   - `insightCtaCallout.variant`: `default | advisory`.
   - closing-band WhatsApp label/message overrides while the number remains centralized, plus an explicit secondary-action visibility flag so “hidden” is not conflated with “use default”.
2. **Small editorial text blocks**
   - `insightLead`.
   - `insightSmallPrint`.
3. **Identity-preserving rich modules**
   - `insightDestinationGrid`.
   - `insightDevelopmentGrid`.
   - `insightCourseGrid`.
   - `insightPartnerLogoGrid`.
   - `insightGuideCards`.

Every item carrying an image must be treated as one identity bundle: reference/name, image asset, alt, caption/label, crop/hotspot and route. Article image overrides win only inside their block and never mutate canonical documents.

## Data-authority rules by module

| Module | Canonical live fields | Article-owned fields |
|---|---|---|
| Destination | location name and route/path segments | approved body, CTA label, caption, placement image/alt override |
| Development | target publication/status gate, title, route, location/country, current price, availability, completion/build state, bedrooms/inventory where shown | ordering, placement image/alt override, mobile grouping/display flag |
| Course | course name, community/destination and canonical route | ordering, action label, optional placement image/alt override |
| Partner | partner identity, public logo, category/slug | ordering and approved service-label override; never referral URL |
| Guide | title, slug/route, audience label, canonical tagline when accepted | ordering and optional approved card-summary override |

## Final approval gate

The implementation is not complete when Sanity accepts the document. It passes only when the actual website-rendered draft satisfies all of the following:

- Standard Insights shell, route, analytics, SEO, related reading and footer remain present.
- Hero matches v15’s split-square composition while retaining required production metadata.
- Six contents entries and anchors are exact.
- Four destination panels, ten development cards, four course cards, eight partner cells and two guide cards are complete and in approved order.
- Development values are current controlled Sanity values at render time; no price/status/completion literals are copied from HTML into frontend code or article fields.
- Monte Rei and Palmares article card overrides are correct and canonical imagery elsewhere is unchanged.
- The exact approved Portugal enquiry and WhatsApp labels/message render with no duplicate action.
- Hero is eager/high priority; every below-fold image is lazy/async with reserved ratio/dimensions.
- Desktop (1280px) and narrow mobile (390px) are compared side-by-side with v15; no horizontal overflow, broken images, empty links, console errors or heading-order failures.
- Interactive elements have visible focus and practical ≥44px targets; the mobile development disclosure exposes all ten and reports state correctly.
- Draft remains unpublished/noindex until James approves that exact actual-site render.
